# Real-World Data Projects

A collection of applied data projects exploring data preparation, regression modeling, and interactive applications with Python and R. The projects work with housing and credit-card data to demonstrate practical steps from raw inputs to reusable outputs.

## 1. Nashville Housing Data Cleaning

### Objective

Prepare housing records for further analysis by applying a repeatable set of data-cleaning transformations.

### Workflow

The notebook:

1. Loads `Nashville_housing_data.csv` into a pandas DataFrame.
2. Inspects sample records, column information, and descriptive statistics.
3. Renames mapped columns to more consistent names.
4. Removes the redundant `Unnamed: 0.1` and `Unnamed: 0` columns, if present.
5. Drops records with missing sale prices.
6. Replaces missing bedroom values with the median bedroom count.
7. Converts sale dates to datetime values, coercing invalid dates to missing values.
8. Trims whitespace and normalizes capitalization in `sold_as_vacant`.
9. Exports `nashville_housing_cleaned.csv` without a DataFrame index.

### Data Fields

The notebook works with property identifiers, land use, addresses, sale dates and prices, vacancy status, assessed values, building characteristics, and bedroom/bathroom counts. Transformations depend on the original column names appearing as expected in the input CSV.

### Run the Notebook

From the repository root, install the Python dependencies and start Jupyter:

```bash
python -m pip install pandas notebook
jupyter notebook
```

Open `clean_nashville.ipynb` and run all cells in order with the notebook working directory set to the repository root.

### Output

`nashville_housing_cleaned.csv` contains the transformed housing records. This is a targeted cleaning workflow, not a guarantee that all missing values, duplicates, outliers, or inconsistent categories have been resolved.

## 2. Credit Card Bill Prediction

### Objective

Demonstrate training and saving a linear regression model, using a prediction function, and presenting predictions through a local Shiny interface.

Although the input filename is `credit_default.csv`, the implemented task predicts a bill amount, not the probability of credit default.

### Workflow

The R script:

1. Reads `credit_default.csv` and assigns a predefined set of 25 column names.
2. Selects credit limit, age, repayment status, and a bill-amount column.
3. Converts the selected values to numeric and removes rows missing any of them.
4. Fits the formula `BILL_AMT1 ~ LIMIT_BAL + AGE + PAY_0`.
5. Generates an example prediction.
6. Saves the model to `bill_prediction_model.rds`.
7. Defines `predict_bill()` for predictions rounded to two decimal places.
8. Builds a Shiny interface accepting credit limit, age, and repayment status.

### Important Target-Column Check

The supplied script selects columns with:

```r
credit_clean <- credit_data[, c(2, 6, 7, 13)]
```

Under the column names assigned earlier in the script, column 13 is `BILL_AMT2`, but the selected target is subsequently renamed `BILL_AMT1`. The app labels its result as a September bill prediction. Resolve this mismatch before interpreting the model output.

If `BILL_AMT1` is the intended target, replace the positional selection with:

```r
credit_clean <- credit_data[, c("LIMIT_BAL", "AGE", "PAY_0", "BILL_AMT1")]
```

Also verify the source CSV's actual column order and definitions: the script overwrites its headers rather than checking their meaning.

### Run the Project

Install R and run the following in an interactive R session with the repository root as the working directory:

```r
install.packages(c("shiny", "promises"))
source("deployment_project.R")
```

The script also includes package-installation calls. After installing dependencies, those lines can be removed or commented out to avoid reinstalling packages on subsequent runs.

The script trains and saves the model before constructing the Shiny application. If sourcing the script does not automatically open the app, launch the objects it creates with:

```r
shiny::runApp(shiny::shinyApp(ui = ui, server = server))
```

Enter a credit limit, age, and repayment status, then select **Predict** to view the estimated bill amount.

### Prediction Function

After running the training and function-definition sections, use:

```r
predict_bill(
  limit_bal = 150000,
  age = 35,
  pay_0 = 0
)
```

The function reads `bill_prediction_model.rds` from the current working directory each time it runs. Confirm the meaning and valid codes for `PAY_0` against the source data documentation before supplying values.

### Outputs and Scope

- `bill_prediction_model.rds`: serialized fitted regression model.
- `predict_bill()`: prediction helper available in the R session.
- Local Shiny application: interactive bill-amount predictions.

The supplied script does not report held-out evaluation metrics, implement a train/test split, validate user input ranges, or configure hosted deployment. Treat it as a modeling and local-app demonstration rather than a validated financial decision system.

## Data Sources and Responsible Use

Original dataset URLs, dataset licenses, and complete data dictionaries are not specified in the supplied project files. Before publishing or redistributing data:

- Document the original source and retrieval date for each dataset.
- Verify permissions and applicable attribution requirements.
- Record units, category definitions, and any changes made to the source files.
- Review identifying information, including property addresses and owner names, before sharing derived data.

Use model predictions for educational exploration only; the project does not establish suitability for lending, credit-risk assessment, or other consequential financial decisions.

## Current Limitations

- Input datasets must be supplied separately.
- The housing notebook's `Suite/Condo` rename key does not match the `Suite/ Condo #` header visible in its saved output; adjust the mapping to the actual input header if consistent naming is required.
- Invalid sale dates become missing dates rather than being repaired or removed.
- Vacancy normalization changes whitespace and capitalization; it does not explicitly map shorthand values such as `Y`/`N` to `Yes`/`No`.
- The credit-card target-column mismatch must be resolved before interpreting predictions.
- Automated tests, pinned dependency files, and hosted app deployment configuration are not included in the supplied project files.
